# GitHub Profile Design

## Goal

Present Jarry as an agent systems engineer who builds reliable, production-minded AI workflows. The profile should make current agent development the main story, while keeping the earlier autonomous-driving software experience as concise context.

## Profile narrative

The opening copy will use a compact English headline focused on agent systems, memory, retrieval, evaluation, and production tooling. The About section will mention:

- Master's and bachelor's education at Shanghai Jiao Tong University.
- Current role as an agent engineer at ByteDance.
- Previous experience as an autonomous-driving software engineer at WeRide, kept to one supporting line.
- Personal interests: strength training, reading, and harmonica.
- Motto: “When things are ambiguous, take one deliberate step forward.”

The tone is precise, confident, and technical without making unsupported claims.

## README structure

1. Header with a short role statement and contact/profile links.
2. About section with current focus and background.
3. Current focus strip covering agent orchestration, retrieval and memory, tool use, evaluation, and observability.
4. Selected work cards linking to `my-co-researcher`, `hybrid-rag-mcp-server`, and other relevant public work.
5. Engineering stack grouped by capability rather than a long logo wall.
6. GitHub activity and statistics modules that remain readable in light and dark themes.
7. Personal footer with the motto and the three non-work interests.

## Project curation

Existing work gets priority. Public agent projects may be forked only when they are relevant to the narrative and useful for future contributions. Planned candidates include OpenAI Agents Python, Microsoft AutoGen, CrewAI, and a lightweight self-hosted agent project. Forks will be labeled by their upstream project and kept separate from original work.

## Contribution strategy

Increase visible activity through substantive, reviewable work: README improvements, examples, tests, evaluation fixtures, documentation, issue triage, and small upstream pull requests. Profile repository commits and changes to personal projects count when they represent real maintenance or documentation work. No empty or content-free commits will be used to manufacture an activity pattern.

## Validation

- Render the README locally and inspect all links, badges, and images.
- Confirm the profile repository is public and named exactly after the account.
- Check that wording distinguishes current agent work from prior autonomous-driving experience.
- Verify that selected project links resolve and that activity widgets use stable URLs.
